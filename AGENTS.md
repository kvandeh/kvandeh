# AGENTS.md

Rules for any agent (or person) editing kcvdh.com. These come straight from Kieran; follow them without being reminded.

## Workflow

- **Work on `main`.** `test` is an old scratch branch.
- **Run `python build.py` after every change** (`GH_TOKEN=$(gh auth token) python build.py` to include `/contributions`). The deploy runs it too, daily and on every push.
- **Look at your own work before calling it done.** Screenshot it at desktop and phone widths, and run Lighthouse. Aim for 100 on accessibility, SEO and best practices.
- **Never invent facts.** Only use what is already on the site, the resume or GitHub. Leave `<!-- TODO(Kieran): ... -->` where something is unknown.

## Single source of truth

- **Header:** the `<header class="topbar">` in `index.html`. `build.py` copies it into every other page. On the homepage the logo chip opens LinkedIn; on every other page it links to `/`.
- **Layout:** every page extends `templates/base.html.j2` (head, SEO tags, AI summary, header, footer). Put HTML in `templates/`, never in Python strings; `build.py` only gathers data and renders.
- **Footer:** `templates/footer.html.j2`. It is included on every generated page and stamped into the homepage.
- **Sitemap, `/site/` and `llms.txt`:** generated by `build.py` from the same list of pages. Never edit them by hand. A new page must show up in all three.
- **Hidden AI summary:** every page has `<section class="ai-summary" hidden>` (from `base.html.j2`, or `ai_summary:` in a page's frontmatter). It must only restate what the page visibly says; never add claims that are not on the page.
- **New pages:** add `pages/<slug>.md` (frontmatter: `title`, `summary` for SEO, `card` for its first-person line on `/site/`, optional `ai_summary`). It becomes `/<slug>/`, joins the sitemap, and gets the header and footer automatically. Add it to the Site column in `templates/footer.html.j2`.
- **Aliases:** add to `ALIASES` in `build.py` (for example `techstack` → `/uses/`). They are redirects with a canonical tag, indexable and listed in the sitemap. Add each new alias folder to `.gitignore`.
- **Generated output is gitignored:** article pages, `pages/` output, `/contributions`, `sitemap.xml`, `llms.txt`.

## Design

- **Same width everywhere:** content uses `--maxw` with `--pad` gutters, like the homepage.
- **No horizontal lines or dividers.** Use whitespace.
- **No hover effects anywhere.** Keep `:focus-visible` outlines for keyboard users.
- **Footer:** column headings link to their page (Projects → `/#projects`, Site → `/site/`, Articles → `/articles/`). Name and role form one link home.
- **Cards are fully clickable:** wrap the whole card in one `<a>`, never just the title.
- **Not everything needs a visible title.** If a heading only labels the obvious, make it `.sr-only` or use `aria-label`, so the page stays accessible.
- **The header nav stays short:** Contributions, Resume, Contact. Secondary pages (Uses, Now) live in the footer.
- **No empty or placeholder pages.** Do not publish a page until it has real content (for example, a bibliography only once Kieran supplies entries).
- **Small UX matters:** long text truncates with an ellipsis, adjacent columns line up in height, and nothing overflows on phones.
- **Reuse existing classes** (`.post`, `.acard`, `.article-grid`, `.foot`) before writing new CSS.

## SEO

- Every page has a unique `<title>`, a meta description, a canonical URL and Open Graph tags (`templates/base.html.j2`).
- Use structured data where it fits: `Person` on the homepage, `BlogPosting` on articles, `ProfilePage` on `/contributions`.
- Grey text must pass contrast (`--faint` is the lightest allowed).
- Images need `width`, `height` and `alt` (`alt=""` if decorative).
